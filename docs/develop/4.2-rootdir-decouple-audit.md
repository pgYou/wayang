# 4.2 改造二落地报告 —— rootDir（dataDir）与 controller-workspace 解耦

> 实施规范：`docs/develop/monorepo-design.md` 第 4.2 节（定稿）。分支 `feat/core-app-decouple`。
> 本文记录 cwd 审计逐点结论与消费点改造落点，作为「cwd 审计结论入改造报告」验收项的持久化载体。

## 注入契约

- `packages/protocol/src/types/paths.ts`：`StoragePaths {dataDir, logDir, cacheDir}` 与 `WorkspacePolicy {controllerWorkspace, defaultWorkerWorkspace}`（barrel 导出于 `types/index.ts`）。不进 `WayangConfig` schema、不参与热更。
- 注入链：宿主 → `ServerMainOptions` / `WayangServerOptions`（`storagePaths?` / `workspacePolicy?`，desktop 程序化注入面）→ `SupervisorOptions` → `SystemContext`（`SystemContextPaths`，必填）。
- 宿主侧构造（apps/cli/server-entry.ts）：`dataDir = <wayangRoot>/.wayang`（现状逻辑不变）；`workspacePolicy = { controllerWorkspace: 启动工作区（argv --workspace-dir / 启动目录）, defaultWorkerWorkspace: <dataDir>/workspace }`。
- `logDir` / `cacheDir` 的 CLI 默认值 = **会话目录**（`<dataDir>/sessions/<id>`，dataDir 的子目录）：新会话目录在 server 侧创建之前宿主不可知，故该默认值在 Supervisor 装配点完成——纯赋值（把已解析的 sessionDir 赋给 logDir/cacheDir），不是反推；宿主可显式注入覆盖（desktop）。默认解析函数 `resolveSessionStoragePaths` / `resolveSessionWorkspacePolicy` 从 supervisor.ts 导出，宿主与测试共用同一语义。
- CLI 默认路径与 0.9.9 逐项一致：会话日志 `<dataDir>/sessions/<id>/wayang.log`；MCP socket `<sessionDir>/.mcp/acp-mcp-*.sock`；通用工作区 `<dataDir>/workspace`；controller 工作区 = 启动目录。无新增 CLI flag。

## 四个消费点改造落点

| 消费点 | 落点 |
|---|---|
| general-workspace | `packages/core/src/infra/general-workspace.ts`：删除 `wayangDirForSessionDir` 反推与 `homedir()` 兜底，`resolveGeneralWorkspace/ensureGeneralWorkspace` 改读注入的 `WorkspacePolicy.defaultWorkerWorkspace` |
| add-task | `packages/core/src/services/tools/add-task.ts`：`deps.workspaceDir` 语义定为注入的 controllerWorkspace（派发基准）；相对声明工作区显式 `base = controllerWorkspace`（`validateDeclaredWorkspace` 第 4 参 / `normalizeWorkspacePath(declared, current)`）；`normalizePath` 相对输入 fail-closed |

| mcp-transport | `packages/core/src/services/agents/acp/mcp-transport.ts`：`mcpSocketPathFor(cacheDir, …)`、`StartMcpTransportOptions.cacheDir`；`acp-mcp-host.ts` deps 改 `cacheDir`；`acp-worker-run.ts` 从 `ctx.storagePaths.cacheDir` 注入 |

### D. 豁免与宿主侧

- 测试文件（`__tests__/` 树、`*.test.ts`）中的 `process.cwd`（server-spawn-e2e 的 CLI 路径、acp transport/real-harness 的 scratch 目录、add-task 系列的相对路径构造）——**确认无害**：测试锚定 vitest 工作目录是合法用途；边界规则与静态扫描测试均豁免测试文件。
- 宿主侧 `apps/cli/src/server-entry.ts` 的 `flags.workspaceDir ?? process.cwd()` **保留**：宿主解析启动目录并作为 controllerWorkspace 注入，正是「宿主归应用」的分工；cwd 禁令只约束 `packages/core/src`。

## 强制手段（fail-closed）

- `scripts/check-boundaries.mjs` 新增第 4 条规则：`packages/core/src` 非测试源码禁止 `process.cwd()`（违反即 exit 1）。
